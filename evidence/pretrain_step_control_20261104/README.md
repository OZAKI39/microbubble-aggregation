# 预训练档步长控制的改进（2026-11-04）

用户同意（2026-11-04“同意上述三项建议”）在不改物理和检查的前提下加快计算。这里记录改了什么、对照了什么，以及为什么把每步移动量的目标从 3% R 改为 0.5% R。

`EXPLORATORY / PRETRAIN_TIER / training_ready=false`。冻结 HF/LF 路径不变。

## 改了什么

1. **直接声场的积分节点只算一次**（`acoustics.gauss_legendre`，按阶数缓存）。原来每步都重算 Gauss–Legendre 节点，约占每步时间的 25%。结果逐位不变。
2. **步长控制**（`integration.integrate_pretrain`，设置在 `configs/pretrain_policy.json` 的 `stepping`）：
   - 每步最大实际位移的目标从 3% R 改为 0.5% R；
   - 步长上限从 0.5 ms 改为 2 ms，团不动时步子可以放大；
   - **记住失败步长**：某个步长没通过检查，之后的步长先限制在它的 0.8 倍，这个限制每接受一步放宽 2%，但不低于最小步长。原来是“失败 → 减半 → 立刻翻倍 → 又失败”。
   - 验证时曾让“需要 OSQP 兜底的步”也触发这个限制。独立代码检查指出：如果某种接触网络在任何步长下都需要 OSQP，这会让步长每步再缩 0.8 倍、无止境地缩小（用强制 OSQP 的测试复现）。所以最终版去掉了这个触发。下表中 0.5% R 的运行都没有发生过 OSQP 兜底，结果不受影响；已重跑确认逐位相同（见“复核”）。
   - 每个被接受的步仍须通过全部同名检查，检查和容差都没有改。
3. 运行配置写 `"step_control": "2026-11-02"` 就用原来的控制（3% R、0.5 ms、无记忆），见 `stepping_earlier`。已核对：随机动作 offset_B 用它重跑，轨迹与 11-04 的原运行**逐位相同**。这同时说明积分节点缓存不改变结果。

## 为什么是 0.5% R：团的整体自转对步长敏感

32 泡已成形团在 X− 单路下会缓慢整体自转（每秒约 3.7°）。把同一条运行（3000 Pa-eq，1.5 s）用不同步长算：

| 步长控制 | 步数 | 需要第二次线性化的步 | 用时 | 1.5 s 时的自转 |
|---|---|---|---|---|
| 固定 0.0625 / 0.125 / 0.25 ms | 24125 / 12246 / 6127 | 2 / 2 / 1 | 124 / 62 / 32 s | 5.57° / 5.57° / 5.57° |
| 原来（3% R，上限 0.5 ms） | 3248 | 2880 | 18 s | 7.20°（+29%） |
| 3% R，上限 1 ms | 1845 | 1439 | 15 s | 12.88° |
| 0.75% R + 记忆 | 2890 | 2521 | 18 s | 8.73° |
| **0.5% R + 记忆（现在）** | 4330 | 360 | 21 s | **5.94°（+7%）** |

- 三种固定小步长的结果相同（位置相差 < 0.01 nm），已收敛。
- 分界在于：接触约束“一次线性化”就能通过检查，结果就收敛；步子大到需要重新线性化后，自转会偏快。原来的 0.5 ms 步已经越过这条线。
- 用“均匀推力、没有力矩”做对照：任何步长都没有自转（`SCRIPTS.txt` 的 uniform_push）。所以自转本身来自声学力，只是转速的数值误差与步长有关。
- 位置、团速、每 px 形状变化、长宽比几乎不受影响，受影响的主要是转速。
- 也试过把“需要第二次线性化”直接当作失败信号。单路运行很准（+2.7%），但随机动作运行里步长被压到约 1 µs，一条要 834 s，所以没有采用。
- 每步移动量就是精度的尺度：除粘附外所有力都与声源强度平方成正比，粘附也按 A_ref² 设定，所以同样的 0.5% R 在 3000 和 6000 Pa-eq 下精度相同。原来的 0.5 ms 上限在 6000 Pa-eq 下相当于每步 3% R，会更不准。

## 对照：完整运行

所有运行 2 条并行（与原来相同），全体耦合、传播延迟、默认粘附、已成形 32/128 泡团。

| 运行 | 原来 | 现在 | 与细步长参考比 |
|---|---|---|---|
| 实验式三段（X− → Y− → X−，3000 Pa-eq，4.5 s），32 泡 | 100 s | **50 s** | 泡位置最大差：原来 0.73 px，现在 0.22 px（参考：固定 0.125 ms，179 s）。4.5 s 自转：参考 11.2°，原来 13.5°，现在 11.9° |
| 同上，128 泡 | 462 s | **128 s** | 两者自转都与参考相同（不需要第二次线性化） |
| 随机动作 center_A，32 泡，2 s | 543 s（15384 步被拒） | **118 s**（679 步被拒） | — |
| 随机动作 offset_B，32 泡，2 s | 317 s（8319 步被拒） | **172 s**（758 步被拒） | 见下 |
| 随机动作 center_B，32 泡，2 s | 2080 s（8392 步被拒；7717 次用了 OSQP 兜底，其中 3298 次达迭代上限） | **139 s**（434 步被拒，没有用 OSQP） | — |

**随机动作运行逐点比较没有意义。** 每 0.1 s 换一次推的方向，团内部会重排；重排的路径对步长很敏感。固定 0.0625 ms 的参考、原来的控制、现在的控制三者之间：泡的位置差到 20 px，团心差 3–5 px，团的长宽比中位数分别为 1.37、1.16、1.07。2026-11-02 的准入记录也写过：“单泡轨迹在重排时对步长敏感”。所以随机动作数据应使用多条运行上的统计量。

为确认这是对步长敏感、而不是没算准，把 offset_B 的前 0.5 s 用更细的固定 0.03125 ms 再算一遍，与各变体比（0.5 s 时）：

| 变体 | 泡位置最大差 | 团心差 |
|---|---|---|
| 固定 0.0625 ms | 19 px | 5.7 px |
| 原来的控制 | 7.7 px | 0.7 px |
| 现在（0.5% R） | 14 px | 6.4 px |
| 0.25% R | 7.7 px | 1.0 px |

步长减半，差别并不随之变小，最细的两个固定步长之间也差到 19 px：随机动作下的重排没有逐点收敛的解。在这一点上，现在的控制既不比原来的差，也不比它好。

## 复核（独立代码检查之后）

另起的代码检查（只读代码，没看本目录的结论）确认：不改设置（`rejection_cap_factor: null`）时步长控制与原来逐位相同。它指出、并已修正的与本项有关的问题：
- 上面所说的 OSQP 触发可能使步长无止境缩小：已去掉，并加了“步长上限不低于最小步长”；测试 `test_rejection_memory_does_not_shrink_steps_without_end` 用强制 OSQP 的情形检查步长序列不受影响。
- `rejection_cap_factor`、`rejection_cap_growth` 没有合法性检查：现在要求 0 < 因子 < 1、增长 > 1。
- 粘附为正而作用距离为 0 时不报错、接受无穷大：现在都报错。
- 积分节点缓存返回的数组可被调用者改写：现在返回副本，阶数必须是正整数。

当时同一工作区里还有贴壁模型和接触滑动阻力的代码；用户只接受了其他各项，同步到仓库前这两项已从代码中去掉。

**用同步到仓库的代码重跑（去掉贴壁和滑动阻力之后）：**

| 运行 | 结果 |
|---|---|
| X− 单路 1.5 s（0.5% R） | 与上表的运行逐位相同 |
| 实验式三段 32 泡 | 逐位相同 |
| 随机动作 center_A | 逐位相同 |
| `step_control: "2026-11-02"` 的随机动作 offset_B | 与 11-04 原运行逐位相同 |
| 6000 Pa-eq 随机动作 offset_B | PASS，用时 1170 s，5581 步用了 OSQP 兜底，最大入射声压 18.4 kPa。原来带 OSQP 触发的版本是 692 s：去掉触发后，这类常需 OSQP 的运行变慢，但不再有步长无止境缩小的风险 |

CPU 测试 50 项通过，4 项 GPU 测试未选（`CPU_TESTS.log`）。
