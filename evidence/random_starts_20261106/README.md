## 做法

`microbubble/initial_conditions.py`：
- `irregular_cluster_3d(n, R, aspect, seed)`：三维不规则泡团。泡一个个从随机方向沿直线飞来，碰到泡团就停；以 85% 的概率贴着碰到的泡朝中心滚，直到碰上第二个泡；再以 85% 的概率沿两泡之间的沟滚到第三个泡（三维里三点支撑才稳）。长出 2n 个泡后，按 x² + (a y)² + (a z)² 从中心取 n 个相连的泡，所以长宽比 a > 1 时沿一个轴拉长。泡与泡接触间隙 10 nm，没有重叠。生成 128 个泡约 70 ms。
- `random_start(seed, ...)`：每条运行的初态。按种子依次取：泡数（16–128 的整数，均匀）、长宽比（1.0–1.4，均匀；1.0–1.4 是原来存好的泡团的范围，用户没给范围，可在策略文件 `random_state.aspect_range` 改）、泡团种子、三维随机朝向（各方向等可能）、通道内的中心位置（沿全长、整个圆截面均匀），每个泡离管壁和端面至少 50 µm。顶部两个孔和运行中的离壁保护一样不考虑。

运行配置只写 `state_seed`（还有 `action_seed`）；手写的 `state`、`offset_m` 已删除。生成的初态记在 `SUMMARY.json` / `EXECUTION.json` 的 `task.start`（泡数、长宽比、泡团种子、旋转矩阵、中心），初始位置就是 `trajectory.h5` 的第一帧。原来存好的 36 个单层泡团不再使用（文件保留）。

## 核查

| 项目 | 结果 |
|---|---|
| 1000 个随机初态（`fig1_start_distribution.png`、`STARTS.json`） | 泡数取到 16–128 的 113 个不同值，均值 73.5；长宽比 1.000–1.400；长轴方向在各方向均匀（与通道轴夹角余弦的均值 0.02）；中心 x 从 −16.17 到 +16.16 mm，截面内铺满；最近离壁 50.3 µm |
| 生成的泡团（`fig2_example_clusters.png`） | 三维、紧实、排列无序；平均每个泡挨着约 5 个泡，没有重叠，全部相连 |
| 示例运行（`fig3_example_runs.png`、`start3d_runs.mp4`，随机动作种子 0，0.3 s，GPU 声场 + C++ 接触步） | 31 泡（种子 11）：PASS，2633 步，10 s；112 泡（种子 0）：PASS，2494 步，174 s |
| 全部测试（笔记本，含 GPU 和 APECSS） | 46 项中 45 项通过；失败的 1 项仍是原来单层泡团文件的逐位复现（服务器 AVX-512 与笔记本的末位差），与本次无关 |

运行成本（笔记本，RTX 4060 Laptop，逐条运行）：每仿真 1 s，31 泡约 35 s，112 泡约 10 分钟。大泡团的接触多（每个泡约 5 个），每步的约束求解更重；112 泡的运行有 81 步交给 Python 版接触步（OSQP）。

## 中间版本：单层泡团（已放弃，`planar_starts_superseded/`）

同一天先做过“从 36 个存好的单层泡团里随机选、水平面内随机转、放到通道内随机位置”的版本。发现单层泡团只要不在通道中心高度（z = 0，四个 PZT 圆片中心的高度），竖直方向的声场力就不对称，0.1 s 内从一层折成 7–12 µm 厚的立体团，运行慢 2–25 倍；在 z = 0 上同一泡团保持一层（`planar_starts_superseded/fig4_folding_snapshots.png`、`folding_side_by_side.mp4`）。用户指出真实泡团本来就是三维的，相机看到的只是剪影，于是改为三维泡团。
