## 计时发现了什么

在 `native/contact_step.cpp` 和 `native/daqp_qp.cpp` 的临时副本里逐段计时（`timed_sources/`，只编译成 scratchpad 里的临时库，项目代码没有因计时而改动）。本机，默认设置，每个初态前 0.1 s：

- 改动前，122 泡时接触步每步约 19–23 ms，其中 **DAQP 的"建立"阶段占 90%**：
  - 把 366×366 的稠密 H（就是阻力矩阵 A）做稠密 Cholesky 分解并求逆；
  - 用它变换全部约 600 行约束；
  - 把热启动猜测的约 360 个贴紧约束逐个加进分解。
- 真正的迭代求解只有约 0.7 ms，复制数据不到 2%。

## 改了什么

**原理：** A 几乎是单位阵，只有贴近的泡对之间有润滑阻力小块。接触步前面已经对它做了稀疏 Cholesky 分解（A = Pᵀ·L·Lᵀ·P，P 是 Eigen 的重新排序置换，约 0.4 ms）。用这个分解把二次规划变换成最小距离问题：
- 变换：z = Lᵀ·P·s，z0 = L⁻¹·P·b，M = B·Pᵀ·L⁻ᵀ，w = z − z0，d = −gap − M·z0；
- DAQP 解 min ½‖w‖²，M·w ≥ d；
- 再变换回来：s = Pᵀ·L⁻ᵀ·(w + z0)。

数学上是同一个问题，乘子（接触力）也完全相同（A·s − b = Bᵀ·λ）。DAQP 不再拿到 H（`H = NULL`、`f = NULL`），也就跳过了稠密分解和约束变换。

**涉及的文件：**
- `native/daqp_qp.cpp`：接口改为 `contact_ldp(n, m, M, d, guess, …)`。原来的 `daqp_qp` 删除；名字没叫 `daqp_ldp`，因为 DAQP 内部已有同名函数。
- `native/contact_step.cpp`：每个有约束的步，用已有的稀疏分解构造 M 和 d（一次稀疏三角求解，右端是约束矩阵的约 600 列），调用 `contact_ldp`，再变换回 s。
- `microbubble/contact.py` 的 `DaqpQP`（Python 版接触步）：同样的形式，用稠密 Cholesky 分解。它只用来对照，不追求速度。
- 热启动、容差、迭代上限、质量门都没变。

## 与改动前估计的出入

改动前我估计接触步能快约 7 倍，实测只快约 1.9 倍（122 泡）。原因是"建立"阶段里有一大块和 H 无关：把热启动猜测的约 360 个贴紧约束逐个加进 DAQP 的分解，每加一个都要和已有的约束做点积，运算量约 k²·n ≈ 4×10⁷。这部分去不掉，改动后仍要约 7.7 ms（122 泡）。DAQP 无法沿用上一步的分解，因为每一步 M 都在变（泡在动，连线方向和阻力都变了）。要再快，得换成能利用约束稀疏结构的算法：约束只通过共享的泡和润滑阻力彼此相关。那是另一项工作，没有做。
